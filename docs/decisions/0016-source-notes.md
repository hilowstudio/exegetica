# 0016: Replies and documents say what they drew on

Recorded 2026-11-03 from the harness proposal (Layer 2 step 8, Layer 5 steps 5 and 8), built at the maker's request to do Phase 5.

**Decision.**

- Each run's tool results are held in memory for that run, for the checks below, and never stored.
- A chat reply that used no library tool shows "No library resource was consulted for this response." under it (worded so on 2026-11-05 at the maker's request; studies saved before then keep the earlier "No library source was consulted."). A reply that used tools lists, under it, any quotation of six words or more that neither the study's library results nor the bundled Bible text holds. The note is saved with the study for display, and the server drops it before history reaches the model.
- The reply check exempts quoted text from its affection pattern only when this run's tool results hold the quotation, or, at six words or more, the bundled Bible text does. A short phrase such as "I love you" occurs in Scripture, so the Bible alone cannot vouch for it. The check follows an open quotation across sentences, so the later sentences of a long quotation count as quoted. A sentence with no quotation marks passes too when this run's tool results hold it word for word, whole or after a short label such as its verse reference, since it is the source speaking. A sentence that mixes the source's words with the bot's own is checked as the bot's. Two fixes of 2026-11-05, after a correct quotation of John 11:14-15 from a fetched passage stopped a reply: separate quotations in one sentence are looked up one at a time rather than run together, and a quotation across a verse boundary is also matched with the bundled passage's verse numbers taken out. The maker decided this on 2026-11-05, after a list of memory verses written without quotation marks was stopped at John 13:34 ("just as I have loved you").
- A finished Generator document is followed by a source check: Scripture references checked against the bundled Bible, and quotations that neither the run's prompt material and tool results nor the bundled Bible text holds. It never blocks a download and never calls anything verified. Revise gets no check, since a revision's sources were the first run's.
- Theology search results give the paragraph number for keyword and Scripture-reference hits. Hits found by meaning come from a chunked copy without paragraph numbers and carry none.

**Why.** A student cannot tell an answer drawn from the library from one the model wrote from memory, and the label says which. Quotation marks were an open door in the reply check: any text inside them passed, so a claim of affection could be wrapped in quotes. The checks say only what was found where. A quotation not found may still be accurate (ESV wording is never stored here), and a reference that exists may still be the wrong one.

**Enforced in.** `webapp/citations.py` (`Recorder`, `quote_check`, `chat_note`, `generator_report`); `webapp/reply_check.py` (quote state, `quote_ok`, and `_source_speaks`); `chat()` and `_generation()` in `webapp/app.py`; `webapp/static/js/chat.js` and `webapp/static/js/generate.js`; `handle_search_theology` in `src/studybible_mcp/server.py`. Covered by `tests/test_citations.py`, `tests/test_reply_check.py`, and `tests/test_chat_route.py`.

**Reverse when.** The label and notes can go if the maker finds them noise. The quotation rule in the reply check changes only with a new decision, since it closes a route around decision 0001.
