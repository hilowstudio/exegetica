# John course pipeline (runbook)

How the Gospel of John course is produced by the resource-generator app. Read this together with `docs/John_Build_Spec.md` (design source of truth), `docs/John_Voice_Guide.md` (the student/parent voice), and `docs/john-framing/_CONSULT.md` (the Theologian workflow). This file is the operational how-to.

## What produces what

- **Generation:** `scripts/john_gen.py` writes Markdown to `docs/john-lessons/` (teacher lesson guides) and `docs/john-materials/` (student reading guides + course docs). It drives the REAL app loop (`webapp.providers.run` over an `MCPBridge`, model `claude-opus-4-8`), so Scripture is genuinely ESV, fetched from the Study Bible tools, not from memory.
- **Publishing:** `webapp/course.py` (manifest) + `webapp/course_views.py` + routes in `webapp/app.py` serve the web view at `/course`; `scripts/course_pdf.py` renders print PDFs into `docs/john-pdf/`.

## Environment (gotchas that will bite)

- Run everything with `.venv/Scripts/python.exe`. That venv has starlette, uvicorn, markdown-it-py, and playwright.
- `john_gen.py` imports `webapp`, so it needs `PYTHONPATH=C:/Users/adam/study-bible`. `course_pdf.py` inserts the root itself.
- Always set `PYTHONIOENCODING=utf-8` (cp1252 breaks on non-ASCII console output).
- ESV: pulled live via the Crossway `BIBLE_API_KEY` in `.env` when a study-bible tool is called with `translation='ESV'`. Never print key values. Subagent Theologian consults do not have the key, so their briefs quote BSB; the generation pipeline supplies ESV.
- ESV in Claude-in-chat: the in-chat `mcp__study-bible__get_passage(translation='ESV')` tool does NOT carry the Crossway key (that server session was started without it), so it returns the "ESV requires a Crossway API key" error. When drafting via the bridge, fetch ESV verbatim by calling the Crossway text API directly with the `.env` `BIBLE_API_KEY` (`https://api.esv.org/v3/passage/text/`, `Authorization: Token <key>`), printing only the returned text. Load the key from `.env` in-process and never echo its value.

## Two ways to run generation (API or subscription)

The inference can run either on the metered Anthropic API or on Claude Code's subscription (no per-token API cost). Same prompts, same tools, same guardrails either way. The only thing that moves is who does the writing.

- **API (unattended batch):** `.venv/Scripts/python scripts/john_gen.py <subcommand> --force`. Uses `ANTHROPIC_API_KEY` (metered). Best for regenerating many docs at once with no chat session. The log records `"source": "api"`.
- **Claude-in-chat (subscription):** move the inference to Claude Code with the emit/ingest bridge:
  1. `<subcommand> --emit` assembles the exact SYSTEM + TASK (framing, sermon, memory line, standards/answer-key rules) and writes it to `docs/_prompts/<label>.md`. No API call, no MCP bridge.
  2. Claude reads that prompt, generates the finished Markdown in chat (grounding Scripture in the ESV with the `mcp__study-bible__*` tools), and saves a draft file.
  3. `<subcommand> --ingest <draft.md>` runs the draft through the same guardrails (`finalize_doc`) and writes it to the out path and log. No API call. The log records `"source": "claude-in-chat"`.

  `--emit` and `--ingest` both skip the API entirely. Use this for interactive unit-by-unit rolling; it shifts the cost to included subscription usage. `--ingest` handles one job at a time.

## How to roll a unit (standard procedure)

For unit `U{N}`, John `X:Y-Z`, lessons `i=a..d`:

1. **Recon.** Read the calendar + current split + sermons for the unit:
   `python` a small script that prints, for `U{N}`, each lesson's `i/date/dow/day_type/lesson_in_unit`, the `docs/john-lesson-passages.json` entry, and `ls docs/john-sermons | grep "John {chapter}"`.
2. **Theologian consult (framing).** Spawn an opus subagent per `docs/john-framing/_CONSULT.md`. Tell it to adopt `src/studybible_mcp/prompts/theologian.md`, read `John_Build_Spec.md` + `John_Voice_Guide.md` + the PRIOR units' framing (`docs/john-framing/U{N-1}.md`, and `U4.md` as the arc target) for continuity, and give it the passage, the calendar day-types, the paired sermon, and the memory-verse status. It returns a framing brief.
3. **Vet it.** Reconcile the brief against the master plan: calendar fit (lesson count, day types, half-days, checkpoints), Build Spec invariants, continuity with taught units, the 16-verse memory plan, sermon consistency, voice, theology. The Theologian advises; you decide.
4. **Write the vetted framing** to `docs/john-framing/U{N}.md` (clean of meta, no em dashes). The `_framing` hook injects it into every lesson and the reading guide.
5. **Recut the split** if needed: edit `docs/john-lesson-passages.json` indices `a..d` to CLEAN verse ranges (`"3:1-8"`, never a descriptive string). Delete any stale prior guide whose passage changed.
6. **Generate:**
   `for c in "reading-guide --unit U{N}" "lesson --index a" ... "lesson --index d"; do PYTHONPATH=... .venv/Scripts/python.exe scripts/john_gen.py $c --force; done`
7. **Review:** grep for em dashes (must be 0), confirm the framing rulings and the memory-verse handling landed, spot-read the reading guide and one lesson.
8. **Render + send:** clear `docs/john-pdf/*.pdf` then `.venv/Scripts/python.exe scripts/course_pdf.py --all --teacher`. Send samples with SendUserFile.
9. **Update the `john-course` memory** with what was built and what is next.

## Deterministic guardrails in `john_gen.py` (do NOT trust the model for these)

The model reliably ignores several instructions, so they are enforced in code:

- **`_dedash(doc)`** converts em dashes to real punctuation (colon by default; comma right after a verse reference; blank for a lone em dash in a table cell). Runs on every doc and teacher key. En dashes (ranges) are kept.
- **`_clean_student(doc)`** (STUDENT_FACING formats) strips leaked pre-title text, the trailing `Standards:` line, splits `## Answer Key` into `*_TEACHER-KEY.md`, and removes any masthead field left as a bare `[...]` placeholder (bold or plain label).
- **`_memory_line(unit_key, kind, passage=None)`** emits the memory instruction. Units in `UNIT_MV` plant/review their verse; every other unit is REVIEW ONLY and says so, or the model invents a different verse in each doc. The 16 anchors: U0 20:31, U1 1:14, U2 1:12, U4 3:16, U6 4:24, U9 6:35, U12 8:12, U14 10:11, U15 11:25, U18 13:34-35, U19 14:6, U20 15:5, U21 16:33, U23 17:3, U25 19:30, U27 21:17. For a plant unit's lessons it is now PASSAGE-AWARE (`_mv_position(mv, passage)` via `_parse_ref`): the verse plants ONLY in the lesson whose passage range actually contains it, reviews in later lessons, and on earlier lessons says "not yet, keep the prior anchors sharp." This is what makes a mid-unit anchor (U6 4:24 sits in L4, not L1) land in the right lesson instead of being misplanted on lesson 1.
- **Calendar `note` passthrough**: `lesson_job` now injects the calendar row's `note` into the brief as `CALENDAR NOTE (...)`, so the master plan's per-lesson day-type shape reaches the model (e.g. Thursdays "single-focus shape"; the half-days "taught as memory quiz + recap"). Half-days (Oct 9, Dec 18, Mar 19, May 7) are recap + memory beats, never dense exposition.
- **`_framing(unit_key)`** injects `docs/john-framing/<unit>.md` into lesson + reading-guide briefs, like a paired sermon.
- **`_reading_title` + the `job["title"]` H1 force**: reading-guide H1s are canonical ("Reading guide, Unit N: name").
- **The VOICE block in `PREAMBLE`** plus the strengthened style rules in `theologian.md` carry the voice. Contrastive negation still leaks occasionally (it is semantic, not strippable); catch it in review.
- **`paired_sermons(passage)`** auto-matches `docs/john-sermons/*.md` by passage overlap and injects the text (capped ~7000 chars).
- **`finalize_doc(job, doc, ...)`** is the one place all the above post-processing runs. Both the API path (`Gen.run`) and the in-chat path (`--ingest`) call it, so a chat-generated doc gets exactly the same cleanup as an API-generated one.

## Publishing details

- **Manifest** (`webapp/course.py`): fuses `docs/john-calendar-map.json` with the scanned files into one index by day/week/month/unit/semester, audience-tagged (teacher = `john-lessons/` + any `*_TEACHER-KEY.md`; student = everything else in `john-materials/`).
- **Web:** `.venv/Scripts/python -m uvicorn webapp.app:app --port 8100`, then `/course`. `?view=teacher` unlocks teacher materials (presentation gating only; needs real auth before any public/parent hosting).
- **PDFs:** `.venv/Scripts/python scripts/course_pdf.py --all [--teacher] [--file X]`. Self-contained: headless Edge via Playwright `channel=msedge`, self-hosted fonts base64-embedded (renders fully offline). Print stylesheet `webapp/static/course-print.css`. Teacher-guide and reading-guide PDFs are named by source file (unique); course docs by title. Clear `docs/john-pdf/*.pdf` before a full re-render to drop orphans from renamed files.
- **Fonts:** `python scripts/fetch_fonts.py` refreshes the self-hosted woff2 (SIL OFL) in `webapp/static/fonts/`. See [[pdf-design]] for the print-typography and engine decisions.
